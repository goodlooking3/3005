# بوابة الإغلاق النهائي

## ما تم تنفيذه داخل المستودع

تمت إضافة إعدادات الإنتاج عبر `--dart-define`، والتحقق من HTTPS، وسياسة access token قصيرة العمر مع تدوير refresh token، وسياسة تسوية تعارضات قابلة للاختبار، واختبارات الموصلات، وسير عمل CI لبناء APK موقّع.

## أسرار CI المطلوبة

يجب إنشاء أسرار GitHub التالية قبل تشغيل `release-*`:

| السر | الاستخدام |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore مشفر بصيغة Base64 |
| `ANDROID_KEY_PROPERTIES` | `storeFile`, `storePassword`, `keyAlias`, `keyPassword` |
| `WASEL_SYNC_ENDPOINT` | endpoint إنتاجي يبدأ بـ `https://` |
| `WASEL_CLIENT_ID` | معرف العميل الإنتاجي |

لا تُحفظ هذه القيم في Flutter أو Git.

## اختبار Android اليدوي الإلزامي

على جهاز Android حقيقي يجب اختبار طلب صلاحية الإشعارات، تفعيل Notification Access، استقبال رسالة اختبار من كل موصل، إيقاف التطبيق وإعادة تشغيله، تسجيل الدخول بالبصمة، إنشاء نسخة مشفرة، نقلها إلى جهاز آخر، التحقق من رفض النسخة التالفة، إنشاء سند، تشغيل المزامنة، وإجبار HTTP 409 للتحقق من ظهور التعارض في سجل التدقيق.

## قرار APK

سير عمل `.github/workflows/android-release.yml` جاهز، لكنه يتطلب أسرار التوقيع وendpoint الإنتاج الحقيقي. بناء APK موقّع دون هذه المدخلات سيكون غير آمن أو سيؤدي إلى إصدار غير قابل للنشر، لذلك لا يتم ادعاء اكتمال APK النهائي قبل توفيرها وتشغيل الاختبار اليدوي.

## معاينة الويب — 2026-10-01

- بُني Flutter Web release محليًا مع `WASEL_WEB_REVIEW=true` و`WASEL_LOCAL_ONLY=true`، وأُضيف بناء الويب إلى بوابة Flutter quality gate.
- أُجري اختبار يدوي على الأرشيف، وإضافة طلب شراء إلى قاعدة المتصفح، ومخزون مشتراه، وفاتورة بيع، وتحديث ملخص المبيعات/التكلفة، ومسار المرتجع.
- كشف اختبار المرتجع أن الشاشة كانت تمرر account IDs ثابتة؛ أُزيلت هذه القيم من الواجهة وأصبح محرك العكس يستخرج حسابي المدين/الدائن من قيد البيع الأصلي. اختبار تكامل regression يستخدم حسابات غير افتراضية.
- هذه المعاينة SQLite/WASM أحادية المستخدم على الجهاز، وليست خدمة إنتاج، ولا تعالج متطلبات المصادقة/المزامنة/سياسات البيانات السحابية أو أسرار APK والتوقيع.
