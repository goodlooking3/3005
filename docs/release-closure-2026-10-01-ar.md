# تقرير إغلاق المعاينة — 2026-10-01

## القرار المختصر

**نسخة Flutter Web المحلية جاهزة للمراجعة البصرية والاختبار اليدوي. المشروع غير معتمد بعد كإصدار إنتاجي مالي أو APK نهائي.** لم تُفعّل استضافة عامة، ويظل وضع المعاينة محليًا بلا خادم أو مزامنة.

## ما أُنجز

- إنشاء/تحديث مستودع خاص باسم `yemenfast/wask-2026-10-01`، مع إبقاء مخرجات `build/` و`.dart_tool/` محلية ومستثناة من Git.
- إعداد هدف Flutter Web مع `sqflite_common_ffi_web` لتخزين SQLite/WASM في IndexedDB، واستخدام imports شرطية لعزل مخازن الويب عن تطبيقات المنصات الأصلية.
- إضافة وضعي `WASEL_WEB_REVIEW=true` و`WASEL_LOCAL_ONLY=true` لعرض تنبيه واضح، وبيانات اختبار اصطناعية، ومنع الاتصال بخادم خارجي في المعاينة.
- تحسين عرض الويب العربية RTL والاستجابة للشاشات، وربط إحصاءات الواجهة ببيانات SQLite بدل القيم الثابتة، وتحديث manifest وواجهة الويب.
- فصل مخطط قاعدة البيانات وترحيلاته، وتجزئة شاشة المرتجعات إلى ملفي library/part ضمن حد حجم الملف الصارم.
- إصلاح عكس قيد البيع: لم تعد شاشة المرتجعات تمرر معرّفات حسابات ثابتة؛ يستخرج المحرك الحسابات من قيد البيع الأصلي، مع اختبار regression بحسابات غير افتراضية.
- توثيق هدف Web في README وGitHub Actions. الـworkflow يبني Web ولا يستضيفه.

## المرور اليدوي في المتصفح

أُجري المرور على origin محلي منفصل وحساب اصطناعي حتى لا تُمس بيانات origin المعاينة الأخرى:

- إنشاء مساحة وتسجيل الدخول، ثم الوصول إلى لوحة نظرة عامة التي تعرض تحذير المعاينة المحلية.
- الأرشيف: البحث بالاسم، فتح خيارات المصدر، وتطبيق WhatsApp؛ تغيرت النتائج إلى السجل المطابق.
- الحسابات: فتح شجرة الحسابات، الأرصدة والأوامر المتاحة.
- المحفظة: إنشاء `QA Wallet` محليًا، ثم التنقل إلى وحدات أخرى والعودة؛ بقيت المحفظة ظاهرة ببياناتها من قاعدة المتصفح.
- المشتريات: ظهرت فلاتر الفئات والمورّدين والمنتجات، وزاد عداد السلة من 0 إلى 1 بعد إضافة منتج.
- المبيعات والمخزون: ظهرت ملخصات المبيعات والتكلفة والربح والمخزون، وفتحت شاشة المرتجعات والإلغاء بحالة فارغة سليمة.
- الموصلات وصندوق الرسائل: ظهرت فئات البحث/التصفية وحالة صندوق الرسائل الفارغ.
- الإعدادات: ظهرت خيارات النسخة المشفرة والاستعادة، مع توضيح أن المزامنة غير مهيأة.

كما سبق توثيق اختبارات التكامل للشراء والمخزون والمبيعات والمرتجعات في مجموعة الاختبارات؛ لا تعني المعاينة المحلية اتصالًا فعليًا بموصل WhatsApp أو SMS أو Messenger.

## تشغيل المعاينة محليًا

من جذر المشروع:

```bash
flutter run -d web-server --web-port 8080 \
  --dart-define=WASEL_WEB_REVIEW=true \
  --dart-define=WASEL_LOCAL_ONLY=true
```

افتح `http://127.0.0.1:8080` وأنشئ حساب معاينة اصطناعيًا. تبقى البيانات مرتبطة بملف تعريف المتصفح وorigin نفسيهما. لتنظيف بيانات تجربة محلية، احذف بيانات الموقع من إعدادات المتصفح؛ لا تستخدم بيانات مالية حقيقية.

لبناء نسخة release محلية فقط:

```bash
flutter build web --release \
  --dart-define=WASEL_WEB_REVIEW=true \
  --dart-define=WASEL_LOCAL_ONLY=true
python3 -m http.server 8080 --bind 0.0.0.0 --directory build/web
```

البناء والخادم أعلاه لا ينشران الملفات على خدمة استضافة. رابط المعاينة المؤقت في مهمة Manus صالح ضمن بيئة Sandbox الحالية فقط؛ استخدم `127.0.0.1` عند تشغيلها على جهازك.

## ما يمنع إعلان الجاهزية الإنتاجية

1. لا يوجد حاليًا backend إنتاجي أو مزامنة/مصادقة مركزية أو صلاحيات/سياسات بيانات خادمية؛ قاعدة المعاينة أحادية المستخدم وعلى الجهاز.
2. يلزم إعداد `WASEL_SYNC_ENDPOINT` حقيقيًا عبر HTTPS و`WASEL_CLIENT_ID`، ثم اختبار العقود، الأمن، الخصوصية، تعارضات المزامنة وسجل التدقيق.
3. يتطلب APK النهائي أسرار توقيع Android المُدارة خارج المستودع، ثم بناءً موقعًا وفحص صلاحيات واشتراطات الخصوصية على أجهزة فعلية.
4. يجب إجراء دورة استعادة/نسخ مشفر على جهاز أو متصفح آخر، واختبار المتصفحات والأجهزة وانقطاع التبويب قبل اعتماد SQLite/WASM للاستخدام الفعلي.
5. يلزم اعتماد الأرصدة والعملات والتقارير وسياسات الوصول من مالك المنتج/المحاسبة قبل إصدار مالي عام.

لا تحفظ مفاتيح أو أسرار داخل Git. ويظل قرار النشر العام مؤجلًا حتى إغلاق هذه البوابات وإتمام الاختبار على جهاز فعلي.
