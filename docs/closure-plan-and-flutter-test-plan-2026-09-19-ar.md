## خطة التنفيذ المرحلية

### المرحلة صفر: تثبيت الأساس وإغلاق الأخطاء الحالية

يجب أولًا تصحيح اختبارات SQLite بحيث تبدأ كل مجموعة بقاعدة نظيفة أو namespace مستقل. يجب إضافة teardown يحذف المستندات المرتبطة قبل حذف الأصناف، أو توفير factory لقاعدة اختبار مؤقتة. ثم يصحح اختبار أرقام قيود المرتجع ليميز بين قيد البيع وقيد العكس. بعد ذلك يعاد تشغيل الاختبارات بترتيب عشوائي للتأكد من عدم اعتمادها على ترتيب الملفات.

يجب أيضًا إغلاق ملاحظات التحليل الساكن، خصوصًا `FormField.value` و`BuildContext` بعد الفجوات غير المتزامنة. لا ينبغي رفع نسخة جديدة قبل أن يصبح التحليل صفر أخطاء وصفر ملاحظات حرجة.

**مخرج المرحلة:** 24/24 اختبارًا ناجحًا، تحليل نظيف، وcommit صغير قابل للمراجعة.

### المرحلة الأولى: المحاسبة والبيانات إلى 10/10

توحّد كل عمليات البيع والشراء والمرتجع والإلغاء والمحفظة في خدمة ترحيل واحدة ذات transaction واضحة. يجب أن يحوي كل مستند رقمًا فريدًا، وحالة، وتاريخًا، ومرجع القيد، وسجل تدقيق. يجب منع تعديل أو حذف المستند المرحّل إلا عبر عملية عكس رسمية.

تُضاف اختبارات للضريبة، الخصم، التقريب، العملات، حدود الائتمان، القيود متعددة الأسطر، إعادة التقييم، الإقفال، وإعادة المحاولة بعد الانقطاع. ثم تُقارن تقارير ميزان المراجعة والربح والخسارة بعينات مرجعية محسوبة يدويًا.

**مخرج المرحلة:** كل مسار مستندي يثبت توازن المدين والدائن وتناسق المخزون والحالة داخل transaction واحدة.

### المرحلة الثانية: المبيعات والمشتريات والمخزون إلى 10/10

تُستكمل دورة الشراء من المورد إلى أمر الشراء والاستلام وتحديث المخزون والقيد والدفع. يجب تعريف سياسة واضحة للتكلفة: متوسط مرجح أو FIFO أو تكلفة آخر شراء، ثم تطبيقها في التقارير دون خلط.

في المبيعات، يجب تثبيت سياسة السعر والضريبة والعملات، ومنع البيع السالب، ومنع المرتجع الزائد، وإظهار أثر كل عملية على المخزون والقيد. يجب دعم جرد وتسوية ومستودعات متعددة إذا كان ذلك ضمن نطاق المنتج النهائي.

**مخرج المرحلة:** سيناريو كامل ناجح: شراء ثم استلام ثم بيع ثم مردود جزئي ثم تحصيل ثم تقرير.

### المرحلة الثالثة: الموصلات وAndroid إلى 10/10

يجب تنفيذ EventChannel أو MethodChannel بين `WaselNotificationListener` وFlutter. يجب تمرير payload منقح يحتوي المصدر والعنوان والنص والوقت فقط، مع فلترة التطبيقات المسموح بها ومنع تخزين أسرار الإشعار غير اللازمة. يجب إضافة شاشة حالة الصلاحية، زر فتح إعداد Notification Access، وإعادة فحص الحالة عند العودة من الإعدادات.

يجب فصل الموصل المحلي عن الموصل الرسمي. WhatsApp Web automation لا يُعتمد كتكامل إنتاجي. أي موصل شبكي يجب أن يملك timeout، retry bounded، idempotency، توقيع طلب أو مصادقة، ومؤشر آخر مزامنة.

**مخرج المرحلة:** رسالة اختبار من كل موصل تصل إلى parser ثم إلى مراجعة ثم إلى سجل أو قيد وفق موافقة المستخدم.

### المرحلة الرابعة: التخزين والنسخ والأمان إلى 10/10

تُنشأ اختبارات ترقية من كل نسخة قاعدة حتى الإصدار 12. يُختبر backup مشفر بمفتاح محفوظ في secure storage، واستعادة ذرية إلى ملف مؤقت، والتحقق من checksum والإصدار، ورفض الملف التالف أو المعدل. يجب اختبار فشل منتصف الاستعادة وعدم فقد قاعدة البيانات الأصلية.

يجب إضافة threat model مختصر يغطي token، النسخ، الإشعارات، deep links، logs، وملفات التصدير. يجب إزالة أي token أو محتوى حساس من السجل.

**مخرج المرحلة:** إثبات استعادة البيانات على جهاز آخر أو profile نظيف مع رفض النسخة الفاسدة.

### المرحلة الخامسة: PDF وExcel والتقارير إلى 10/10

يجب إضافة خط عربي مرخص إلى assets واستخدامه في PDF. يُختبر اتجاه RTL، الأرقام العربية واللاتينية، العملات، الجداول متعددة الصفحات، والأسماء الطويلة. لا يكفي فحص حجم الملف؛ يجب فحص النص المستخرج أو الصورة الناتجة.

يجب تعريف قوالب Excel رسمية مع نسخة schema، ومنع التكرار، ومعاينة قبل الاستيراد، وتقرير أخطاء صفّي قابل للتنزيل.

**مخرج المرحلة:** ملفات PDF وExcel قابلة للقراءة والطباعة والمراجعة في Android وWindows.

### المرحلة السادسة: CI والإصدار إلى 10/10

يجب فصل quality gate عن build gate. يمنع quality gate الدمج عند فشل التحليل أو الاختبار. يشغّل build gate بناء Android local وWindows local بعد نجاح الجودة. لا يُبنى APK الإنتاجي إلا بعد توفير secrets داخل GitHub Actions.

يجب تثبيت إصدارات Flutter وJava وGradle بدل الاعتماد على `stable` المتغير. يجب حفظ artifacts وchecksums، وفحص عدم وجود secrets داخل artifact. بعد ذلك فقط ينفذ build signed APK وWindows installer.

**مخرج المرحلة:** artifacts قابلة للتثبيت، checksums منشورة، وسجل CI ناجح من commit نظيف.

يجب اختبار أن زر الترحيل لا ينفذ مرتين، وأن الرجوع أثناء العملية لا يترك transaction معلقة، وأن رسالة الخطأ لا تعرض stack trace أو token.

### اختبارات Android على جهاز حقيقي

يجب تنفيذ القائمة التالية بعد توفير APK تجريبي، وليس في هذه المرحلة النهائية:

1. تثبيت التطبيق على Android 12 أو أحدث.
2. تشغيل الوضع المحلي والتحقق من عدم طلب endpoint شبكي.
3. إنشاء حساب وتسجيل الدخول والخروج وإعادة فتح التطبيق.
4. تفعيل Notification Access ثم إرسال رسالة اختبار من كل تطبيق مدعوم.
5. التحقق من وصول العنوان والنص والوقت إلى Flutter مع إخفاء البيانات غير اللازمة.
6. اختبار رفض رسالة بلا مبلغ أو بعملة غير معروفة.
7. اختبار الإشعارات، البصمة، قفل التطبيق، وإعادة التشغيل.
8. إنشاء نسخة احتياطية مشفرة واستعادتها على profile أو جهاز آخر.
9. تعديل النسخة أو إتلافها والتحقق من الرفض دون حذف النسخة الأصلية.
10. إنشاء سند، بيع، مرتجع، تصدير PDF، طباعة، ومشاركة ملف.
11. تشغيل المزامنة مع endpoint تجريبي، وفشل الشبكة، وHTTP 409، وإعادة المحاولة.
12. فحص logcat بحثًا عن token أو محتوى مالي غير لازم.
