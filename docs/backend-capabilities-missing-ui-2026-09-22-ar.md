# تقرير الوظائف الخلفية غير الظاهرة في الشاشات

**التاريخ:** 22 سبتمبر 2026

**نطاق التدقيق:** وظائف Dart/Flutter الموجودة في `lib/data`, `lib/services`, وطبقات `application/data` داخل الميزات، ومقارنتها بمسارات الشاشات الحالية.

**الهدف:** تحديد ما يحتاج ربطًا بالواجهة فقط، ومنع إعادة بناء وظيفة موجودة أصلًا في الخلفية.

## ملخص تنفيذي

التطبيق يحتوي على طبقة خلفية واسعة وفعالة، لكن ليست كل وظائفها متاحة من مسار مرئي. الفجوات الأهم ليست في وجود الخدمات، بل في غياب شاشة أو زر أو controller يستدعيها ويعرض نتيجتها للمستخدم. الأولوية المقترحة هي المحاسبة المالية المتقدمة، ثم استيراد دليل الحسابات، ثم إدارة أسعار الصرف، ثم أدوات استيراد وتصدير المحافظ.

لا أوصي حاليًا بإعادة كتابة أي repository أو engine؛ المطلوب في معظم البنود هو إنشاء شاشة صغيرة أو controller مستقل وربطه بالخدمة الموجودة، مع الالتزام بحد 400 سطر للتحذير و500 سطر كحد أقصى.

## الوظائف غير الظاهرة أو غير المرتبطة بالكامل

| الأولوية | الوظيفة الخلفية الموجودة | الملف/الطبقة | الحالة المرئية | المطلوب للربط |
|---|---|---|---|---|
| P1 | دفتر الأستاذ العام مع نطاق زمني وحساب محدد | `lib/services/report_service.dart` — `generalLedger` | شاشة التقارير الحالية تعرض يومية عامة مبنية على controller مختلف، ولا تعرض فلاتر التاريخ والحساب التابعة للخدمة | إضافة controller تقارير مالية يستدعي الخدمة، مع حقلي تاريخ وحساب وشاشة نتائج مستقلة |
| P1 | ميزان المراجعة | `ReportService.trialBalance` | لا توجد نتيجة مرئية مخصصة لميزان المراجعة | إضافة تبويب أو شاشة ميزان مراجعة مع إجمالي المدين والدائن والتحقق من التوازن |
| P1 | الأرباح والخسائر | `ReportService.profitAndLoss` | لا توجد شاشة ظاهرة للنتيجة | إضافة بطاقة تقرير أو تبويب يعرض الإيرادات والمصروفات وصافي الربح |
| P1 | التدفق النقدي | `ReportService.cashFlow` | لا توجد شاشة ظاهرة للنتيجة | إضافة تبويب تدفق نقدي يعرض الداخل والخارج والتاريخ والبيان |
| P1 | استيراد دليل الحسابات من Excel | `AccountImportService.importXlsx` | لا يوجد زر اختيار ملف واستيراد داخل دليل الحسابات | إضافة زر استيراد، نتيجة بعدد المستورد والمتجاوز والأخطاء، دون تكرار خدمة الاستيراد |
| P1 | إدارة أسعار الصرف | `CurrencyRepository.saveRate` وعمليات قراءة الأسعار | سياسة العملات تستخدم الأسعار عند الترحيل، لكن لا توجد شاشة واضحة لإدخال سعر صرف مؤرخ | إضافة شاشة أسعار صرف مرتبطة بالشركة والعملات مع منع المعدل غير الصالح |
| P2 | استيراد وتصدير كشف المحفظة CSV/XLSX | `WalletStatementImporter` | المحفظة تعرض الإضافة والتحويل، لكن لا يظهر مسار ملف للاستيراد أو التصدير | إضافة زري استيراد وتصدير وربطهما بـ `WalletProvider.importTransactions` |
| P2 | إنشاء نية تحويل عبر Deep Link | `DeepLinkAutomation` | لا توجد واجهة ظاهرة لتوليد/فتح رابط التحويل | إضافة خيار داخل حوار التحويل بعد اعتماد سياسة المنصة والصلاحيات |
| P2 | المزامنة وإعادة المحاولة التلقائية | `SyncService` | يوجد إعداد للمزامنة، لكن يلزم اختبار أن المفتاح يبدأ الخدمة ويعرض حالة آخر مزامنة | إضافة حالة مزامنة مرئية وزر مزامنة الآن وسجل أخطاء مختصر |
| P2 | النسخ والاستعادة البرمجية | `BackupService` و`SecureBackupService` | توجد أزرار إعدادات، لكن مسار اختيار الملف، نتيجة الاستعادة، ومعالجة الأخطاء يحتاج اختبار قبول مرئي | تحسين الربط الحالي فقط: اختيار ملف، عرض عدد السجلات، ورسالة فشل مفهومة |
| P2 | تصدير تقارير وقيود متعددة الصيغ | `ExportService` | توجد خدمات PDF/Excel، لكن لا يظهر لكل تقرير مسار تصدير واضح | ربط زر تصدير مستقل بالنتيجة الحالية، مع عدم إضافة منطق تصدير جديد داخل الشاشة |
| P3 | تسجيل الموردين وجلب كتالوج السوق البعيد | `RemoteMarketplaceApi` | التنفيذ الحالي محلي شكلي (`LocalMarketplaceApi`) ولا توجد خدمة بعيدة فعلية | لا يُربط قبل تحديد API حقيقي؛ المطلوب حاليًا إظهار حالة محلي/بعيد بوضوح لا ادعاء التكامل |
| P3 | تبديل الحساب/المحفظة ودليل جهات اتصال الهاتف | نماذج الأطراف والمحافظ موجودة، لكن لا يوجد Contacts API | أرقام الأطراف تظهر، ولا يوجد اختيار من دليل الهاتف | يحتاج قرار صلاحيات Android/iOS قبل التنفيذ؛ لا يضاف كود عشوائيًا |

## وظائف موجودة ومربوطة بالفعل

هذه البنود ليست فجوات ربط أساسية، ولا ينبغي إعادة تنفيذها:

- دليل الحسابات: الشجرة، البحث، التصفية، الإضافة، التعديل، الأب، العملة، الرصيد، التفعيل والإيقاف.
- سند القبض والصرف والقيد اليومي: محرر السند واختيارات الحساب والطرف والترحيل موجودة داخل مساحة المحاسبة.
- دفتر الأطراف: الإضافة والعرض موجودان داخل تبويب الأطراف.
- المحفظة الأساسية: إنشاء المحفظة، الحساب، الحركة، التحويل، الفلاتر، والربط بالقيد موجودة.
- المبيعات والمشتريات والمخزون: الشاشات والمحركات والجسور المحاسبية موجودة.
- مركز الموصلات والرسائل: الشاشة والخدمات الأساسية للاستيراد والتحليل والترحيل موجودة.
- المصادقة الأساسية: البريد/الهاتف، تذكرني، البصمة، وتغيير كلمة المرور موجودة في المسارات الحالية.

## ملاحظات على نتائج البحث الآلي

ظهور دالة في قائمة «لا يوجد لها استدعاء» لا يكفي لإثبات أنها مهجورة؛ بعض الدوال تُستدعى بشكل غير مباشر عبر واجهات أو اختبارات، وبعضها جزء داخلي من خدمة. لذلك صُنفت النتائج بعد قراءة الملفات ومسارات التنقل، لا اعتمادًا على البحث النصي وحده.

## خطة الربط المقترحة

### المرحلة الأولى: إغلاق اختبار دليل الحسابات

يجب إكمال اختبارات Widget لمسار الإضافة والبحث، ورفض الرقم المكرر، وتعديل الحساب، وإظهار الحساب بعد إعادة تحميل الشاشة. يوضع الاختبار في ملف مستقل أقل من 500 سطر.

### المرحلة الثانية: التقارير المالية

يُنشأ `financial_reports_controller.dart` ثم شاشة أو تبويب تقارير مستقل يستدعي `ReportService` دون نسخ SQL أو منطق الحساب. يظل كل ملف أقل من 400 سطر قدر الإمكان.

### المرحلة الثالثة: استيراد دليل الحسابات وأسعار الصرف

تُضاف أزرار وواجهات اختيار الملفات وإدخال الأسعار فقط بعد اختبار الخدمات الموجودة مباشرة. لا يتم تعديل `accounting_repository.dart` أو `main.dart` لهذه الإضافات إلا عند الضرورة.

### المرحلة الرابعة: أدوات المحافظ

يُربط الاستيراد والتصدير الموجودان في `WalletStatementImporter` بشاشة المحفظة، ثم يضاف سجل نتيجة واضح. أما Contacts API وDeep Link فيحتاجان قرار صلاحيات ومنصة قبل التنفيذ.

## القرار

الفجوات الحالية هي **فجوات عرض وربط واختبار** في المقام الأول، وليست نقصًا عامًا في طبقة البيانات. البداية الصحيحة هي إغلاق اختبارات دليل الحسابات، ثم ربط التقارير المالية الموجودة، مع عدم تشغيل GitHub Actions حتى اكتمال جميع الإصلاحات المحلية كما طلب المستخدم.
